# NBA Edge Model

End-to-end NBA prediction system covering **game props** (spread, moneyline, total) and **player props** (points, rebounds, assists, etc.) — data ingestion → team power ratings / ML models → market-line comparison → daily picks output.

Game props are the primary focus: a market comparison against real sportsbook lines, with edge and confidence tiers computed directly against DraftKings odds. Player props remain a fully separate, independently-calibrated ML pipeline (see [Player Props](#player-props) below).

## Game Props

Spread, moneyline, and total (O/U) picks for today's NBA games, generated by comparing a team power-rating model against live DraftKings lines.

**1. Team power ratings** (`src/models/team_ratings.py`) — a blend of two signals per team:
   - **SRS** (Simple Rating System) — an opponent-quality-adjusted full-season margin rating, solved iteratively (`rating[i] = avg_adj_margin[i] + avg(rating[opponents_of_i])`).
   - **L10 form** — rolling recent-form margin, home-court-neutralized.
   - Combined `0.65 * SRS + 0.35 * L10`, falling back to official NET_RTG during early-season cold starts.
   - **Per-team home-court advantage** — computed from each team's actual home/road margin split over the last 3 seasons (not a league-wide flat number), capped to a sane range. Playoffs use a flat 3.0-pt HCA instead, since per-team playoff samples are too small to be reliable.
   - **Rest/back-to-back adjustments** and **playoff series momentum** (a small uplift toward whichever team is leading a series) round out the spread.

**2. Totals (O/U) model** — predicts combined score from each team's offensive/defensive rating and pace (`src/models/team_ratings.py` feeds `scripts/generate_todays_team_picks.py`'s `predict_game_total()`): `(home_off_rtg + away_def_rtg)/2 * pace/100` per side, with a playoff scoring-dip factor (0.955×, calibrated to ~5% lower playoff scoring). This model is directional but not yet calibrated against closing lines — see "Current limitations" below.

**3. Edge & confidence tiers** — every game is compared against live ESPN/DraftKings lines:
   - Spread edge = model spread − market spread (same-direction gap, not just picking a side).
   - Moneyline edge = model win% − no-vig market-implied win%.
   - Tiers: **STRONG** (≥5.5 pt spread gap or ≥12% ML edge), **LEAN** (≥3.5 pt / ≥7% ML edge), **MONITOR** (2–3.5 pt gap, flagged but not a pick).

**4. Market-line snapshots & CLV** — every pick-time odds fetch is persisted to a `game_odds` table (`src/data/odds_store.py`), tagged by when it was captured (`pick_time` vs `closing`, the latter via `scripts/capture_closing_odds.py` run near tip-off). This makes **closing-line value (CLV)** computable in `scripts/log_team_results.py` — the standard way sharp bettors validate a real edge before results even come in, since consistently beating the closing line correlates with long-run profitability independent of any single game's outcome.

**Current limitations (being honest about where this stands):**
- Market-line history is being captured going forward from when this was built — there isn't yet a multi-week sample to report a real backtested ROI/CLV number. The LEAN/STRONG thresholds above are hand-set, not yet empirically calibrated against real market data.
- The totals model is a formula, not a trained model — a candidate for a proper HistGBR-style fit once enough real O/U outcomes accumulate.
- No injury/lineup-news awareness yet — the model is box-score/rating-driven only. Always verify injury reports before betting.

## Player Props

**1. Data pipeline** — pulls 7 seasons of player game logs from the NBA API into SQLite. 129,534 player-game rows across 1,178 players (2019–2026). Incremental daily update mode re-pulls the current season to pick up new games (`--update`).

**2. Feature engineering** — rolling windows (L5/L10/L20), hit-rate frequencies, pace/matchup context, rest and travel flags, opponent defensive ratings. ~125 features per player-game.

**3. Model training** — `HistGradientBoostingRegressor` per stat (PTS, REB, AST, FG3M, PRA, REB_AST). Trained on 2019–2024 (5 seasons, 59,950 rows), validated on 2024-25, tested on 2025-26. Key hyperparameters: `max_depth=3`, `min_samples_leaf=30`, `l2_regularization=5.0`, `max_features=0.6`. Feature selection drops inter-correlated features (r > 0.92) and keeps the top 40 by target correlation.

**4. Probability calibration** — predictions are blended 40% L10-baseline / 60% model (`config.settings.BLEND_L10_WEIGHT`), then mapped to P(over line) via a Gaussian CDF using the player's rolling standard deviation. A minimum-minutes filter (min_L10 ≥ 20) removes garbage-time noise before confidence scoring. The 40% weight is a single value unified across every prediction path in the codebase (previously three different, undocumented ratios — 0%, 50%, and 65% — were hardcoded independently in different scripts). It was derived empirically: pooling all 112,422 picks across all 6 stats from a full calibration audit and grid-searching L10 weight in [0.0, 1.0] for the value minimizing pooled Brier score (see `config/settings.py`'s `BLEND_L10_WEIGHT` comment and `data/diagnostics/blend_audit.csv` for the full derivation, including per-stat optimal weights, which vary from 0.15 to 0.65 — this single pooled value is a compromise across stats, not independently optimal for each one).

**5. Live picks** — auto-fetches today's NBA schedule and team rosters from NBA.com, builds current-form features for each player, and outputs two SAFE Flex cards. No manual player ID input required.

**6. Backtest** — held-out 2025-26 season. Hit rates reported per stat at multiple confidence thresholds. Composite markets (PRA, REB_AST) use summed component model predictions rather than a single composite model.

## How to Run

The default CLI uses live sportsbook prices, with no Sleeper account, screenshots,
or manual app lines required:

```bash
python scripts/run_daily.py            # archive live evidence, then run the daily workflow
python nba.py picks --props-only --quick # scan props using refreshed model data
python nba.py bets --reuse --price "Nikola Jokic PTS over 24.5 -110"
python nba.py grade                    # grade saved market candidates after games
```

Market candidates and prices are saved in `data/market_picks/YYYY-MM-DD.json`;
the fair-probability board is in `data/fair/YYYY-MM-DD.json`. These are model
candidates, not placed wagers. Automatic sportsbook coverage depends on the
books ESPN exposes; `--price` accepts odds from any app. Opening-season spread/ML ratings blend prior-season strength (regressed 20% toward league average) with current results using a 20-game prior. Teams need ten current-season games or twenty prior-season games. Totals retain the ten-current-game requirement. Player props require ten appearances with 12+ minutes in the last 365 days, including prior seasons. Their model signal starts at half strength relative to market consensus and rises to full strength over ten current-season appearances. These prior weights are conservative defaults, not newly validated calibration parameters. Unavailable grading results remain pending rather than becoming DNPs. The older pick'em card workflow
remains available with `python nba.py picks --pickem`.

**Game props:**

```bash
# Generate today's spread/ML/O-U picks (also snapshots market lines for CLV)
python scripts/generate_todays_team_picks.py --save
# or: make game-picks

# Capture the closing line near tip-off (separate run, enables CLV)
python scripts/capture_closing_odds.py
# or: make capture-closing-odds

# Grade yesterday's picks (spread/ML/O-U + CLV once a closing snapshot exists)
python scripts/log_team_results.py

# Cumulative performance report
python scripts/log_team_results.py --report
```

**Player props:**

```bash
# 1. Pull data (full backfill, run once — ~2h due to API rate limits)
python scripts/pull_season_data.py --backfill

# Or pull a single season
python scripts/pull_season_data.py --season 2025-26

# Daily update (re-pulls current season to pick up new games)
python scripts/pull_season_data.py --update

# 2. Build features
python -m src.features.pipeline

# 3. Train models
python -m src.models.player_props

# 4. Generate today's picks (auto-fetches schedule and rosters — no args needed)
python scripts/generate_todays_picks.py

# 5. Run backtest report
python -m src.models.edge_finder
```

## Design Notes

- **Ingestion skip logic fix** — the original ingestion pipeline skipped players already logged, making `--update` a no-op for the current season. Fixed by adding a `force_update` flag that bypasses the skip check and relies on SQLite's `ON CONFLICT DO NOTHING` to handle duplicates safely.
- **Forward-looking picks** — the picks generator now auto-fetches today's schedule and current rosters from NBA.com rather than requiring manual player IDs or a pre-existing feature row for today's date.
- **Temporal integrity** — all rolling features use `shift(1)` after groupby to ensure no data leakage: a game's features are computed exclusively from games played before it.

### Combined player + game stack screen

`nba picks` (market mode) and `nba daily` now finish with a combined screen,
written to `data/prop_stacks/DATE.json`. Run it separately after generating both
scans with `python scripts/build_prop_stacks.py`. It ranks saved player props
and game moneylines by estimated hit probability (at least 70%) while requiring
at least 4% estimated expected return. It considers two- and three-leg stacks
from different games at the same named sportsbook, excluding overlapping teams.
These thresholds are policy defaults, not validated measures of safety.

Spread and total scans continue in the team pipeline; they cannot enter stacks
until calibrated hit probabilities and executable prices exist. Stack payout
products are indicative only. Approval stays disabled pending validated joint
probability evidence and an executable combined quote. No qualifying stack means
PASS, never forced legs. This report reads saved scans rather than refreshing
quotes; rerun the market scans and review current prices before using its output.
