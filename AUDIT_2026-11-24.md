## Items → file:line → root cause → planned fix

**1. Sportsbook feed silently dead.**
Where: `src/betting/quote_quality.py:6-19` (gate), `src/betting/eligibility.py:11` (`MAX_QUOTE_AGE_SECONDS = 900`),
`src/data/espn_props.py:159-184` (rejection), `scripts/find_bets.py:96,297,553` (prints 0 and exits 0),
`nba.py:411` (OK = exit 0).
Cause: the ESPN DK feed really is stale or future-stamped (not a parse bug), and every stage reports exit 0
even when it produces nothing.
Fix (1a): move the 900 s window into config. Make the parser explicitly accept epoch-ms and offset ISO
strings, and reject naive strings, with tests. Report the before/after pass count on today's snapshot; I expect it
to stay 0, because the honest fix is 1b. (1b) Add a `WARN` status: any stage with input > 0 and output 0
prints `WARN (exit 0) — label: <reason>`, and run_daily ends with `WARN` exit code 3. Chips show yellow/red.

**2. Injury filtering incomplete or invisible.**
Where: `worker/prop_worker/slate.py:47-49` (EXCLUDED = OUT/D/Q/GTD; "probable"/"available" pass),
`:136-157` (official first, ESPN fallback), `card.py:53,151` (counts only), `today.py:568-571` (anonymous count).
Name matching already strips diacritics and suffixes (`names.py:16-25`); 1 unmapped row today (Zack Austin, CLE).
Cause: the exclusions aren't named, there's no timestamp, an unknown status fails *open* (`STATUS_CODE.get(..., status)`
returns raw text that isn't in EXCLUDED), and there's no staleness check.
Fix (1c): EXCLUDED adds `DTD` and any status not in a known-safe set {PROBABLE, AVAILABLE} (fail closed).
When official and ESPN disagree, the stricter one wins (today: official P vs ESPN Day-To-Day → excluded).
Store `as_of`/`source` per leg, plus the newest report time in card JSON. Mark the board STALE if the
newest injury row is older than `INJURY_MAX_AGE_H = 3`. Unmapped injury names are listed in Excluded.

**3. Roster/game mapping invisible.**
Where: `slate.py:193-202`. A team that matches neither side keeps the row with `opp=None`; it isn't dropped.
Cause: game comes from the market's `game_id` (Kalshi/PropLine), team from `players.team_abbr`, and
nothing enforces that they agree.
Fix (1d): if the roster team isn't in {home, away}, drop the prop into Excluded with reason "team mismatch" (roster
team, game, roster as-of). The card JSON gets `team`/`opp`.

**4. Overconfident p.**
Where: `card.py:43-48,60-68,81-94` (raw p drives every rule and max price), `daily_brief.py` ledger
report (mean p .728 vs .673 actual, n=147).
Cause: the formula has never been fit. The hit-rate term uses a +0.5/+1 prior on L10 and has no regression to the mean.
Fix (2b/2c): `src/models/calibration.py`. Primary training set: a **replay of the card formula on every
historical pregame Kalshi quote** in Supabase (`kalshi_quotes` since Oct) against game_logs outcomes,
which gives far more rows than the 147 ledger bets. Use isotonic regression when a stat/venue has ≥ 1,000 rows,
otherwise Platt; shrink toward the ledger offset when small. Card rules and max price use calibrated p.

**5. Blend ratios conflict.**
Where: `config/settings.py:68` `BLEND_L10_WEIGHT = 0.40` (ML path; used by `player_props.py:56`,
`edge_finder.py:82`, `playoff_backtest.py:45`, `dashboard/app.py:37`); **stale text**
`dashboard/app.py:499` says "65% L10 / 35% model"; card `card.py:43` `W_HIST, W_MKT = 0.35, 0.65` (a different
quantity: history vs no-vig market); `scripts/phase1_calibration_audit.py:50-52,395-396` hard-codes 0.65/0.50
(research script). `team_ratings.py:55-56` 0.65/0.35 is SRS vs form for team ratings, not a prop blend (left alone,
but moved to config for consistency).
Fix (2a): one `config/settings.py` section (the existing config module). The card imports it as well; the dashboard text
is generated from the values.

**6. Grading gaps.**
Where: `nba.py:218-219` (grades only `yesterday`), `scripts/log_team_results.py:549-551`,
`scripts/log_pick_results.py`. Worker `grade`/`bets` jobs: green with 0/0.
Cause: no catch-up for missed days (11-21..23 not run → 11-20 picks never graded).
Fix (3a): `nba.py grade-backfill --since 2026-11-17`: grade every date with a picks file and no result rows
(idempotent; skips already-graded dates). run_daily calls it instead of yesterday-only. Lag > 1 game day → WARN.

**7. Player Lookup uses 2024-25 test set.** Where: `dashboard/app.py:681-760` (`season == "2024-25"` at :712).
Fix (4c): current-season game log from local `data/nba_edge.db` (current through the last refresh), old view behind a toggle.

**8. Backtest/Calibration only PTS/REB/AST.** Where: `dashboard/app.py:42-43` (`CALIBRATED_STATS`), `:199-216`.
Fix (3b): all 6 models plus threshold (`N+`) markets. Re-verify the July null-row fix with a row-count test.

**9. Props board exposes little.** Where: `today.py:517-571`; card JSON lacks team/opp/hit rates
(`card.py:243-251`) even though `slate.Prop` has them (`slate.py:221-225`). Kalshi: every strike is evaluated
(`card.py:193`), but only those clearing the thresholds are emitted.
Fix (4b/4d): enrich the card JSON (team, opp, L5/L10/L20/season/H2H, L10 values, MIN L10, p_raw, p_cal, edge, every
strike), with a sortable table and CSV download.

**10. No health indicator.** Where: chips = exit codes only (`today.py:42-53,467-469`; `nba.py:411`);
`job_runs` is never read by the dashboard.
Fix (1b + 4a): WARN status in the run log, plus a health panel from Supabase `job_runs` (latest per job), local
SQLite max(game_date), newest injury row, newest quote per book, and grading lag.
